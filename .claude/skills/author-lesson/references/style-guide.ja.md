# Rise Path 教材 日本語スタイルガイド

Rise Path の教材（`locale: "jp"`）を書く・直すときの文体ルールです。目標は「よい先生が隣で話して
いるように読める日本語」です。翻訳調や説明書調にしないでください。
機械的に確かめられる項目は `npm run lessons:lint` が警告します（括弧内はルール名）。

## 1. 文体

- **です・ます調**で統一します。体言止めを続けない（見出し・表・リスト項目は体言止めで可）。
- **1 文 60 字以内**（`sentence-length`）、**1 段落 160 字以内・3 文まで**（`paragraph-length`）。
  1 文に言いたいことは 1 つです。「〜ので、〜が、〜して」と続けず、文を分けます。
- 主語と述語を近づけます。長い修飾語は後ろの文に回します。
- 学習者に圧をかけない。**禁止表現**（`banned-phrase`）: 「簡単です」「簡単でしょう」
  「簡単にできます」「誰でも」。同じ理由で「当然」「言うまでもなく」「〜すればいいだけ」も避けます。
- 失敗を責めない。「間違えても大丈夫です。どこで止まったかを見ればわかります。」のように、
  次の行動を示します。
- 呼びかけは「あなた」より、主語を省くか「〜してみましょう」を使います。

## 2. 用語

- 新しい用語は**使う前に定義**します（`definitions` ブロックと `glossary`）。2 回目以降は
  `[[用語]]` でリンクします。
- カタカナ語は**初出で英語を併記**します: 参照（reference）、デプロイ（deploy）。
  2 回目以降はカタカナだけで書きます。
- 1 セグメントで新しく出す用語は **3 つまで**です。
- 同じものを同じ名前で呼びます（「フロントエンド」と「画面側」を混ぜない）。glossary の
  `term` と本文・図のラベルを一致させます。
- 略語は初出で正式名を書きます: API（Application Programming Interface）。

## 3. 表記

- 英数字は半角、括弧と句読点は全角（「、」「。」「（）」）。
- 和文と英数字の間にスペースは入れません（「AIに依頼する」「Gitのコミット」）。
  インラインコード（`npm run dev`）の前後だけは半角スペースを入れて構いません。1 つの
  レッスンの中で揺らさないこと。
- 強調は **太字** を 1 段落に 1〜2 か所まで。斜体は日本語では使いません。語句の引用や
  画面上の文言は「」で囲みます（「保存」ボタン）。
- 数字と単位もスペースなしで書きます: 3つ、10分、512MB。範囲は「〜」で書きます（3〜5個）。
- キー操作は `steps[].keys` に入れ、本文では「Ctrl + S」のように書きます。
- 漢字が続きすぎないようにします（目安は漢字 3 割）。「行う」「出来る」「〜の為」は
  「おこなう／する」「できる」「〜のため」と開きます。

## 4. 説明の組み立て

- 段落の最初の文で要点を言い、次の文で理由か例を足します。
- 抽象 → 具体の順にせず、**具体的な場面 → 仕組み → 言葉の定義**の順にします。
- たとえ話は定義の前に 1 つだけ置き、どこが対応しているかを明示します（「客席＝画面」）。
  確認問題でたとえ話そのものは問いません。
- 「なぜ必要か」「ないと何が困るか」を先に示してから、「どうするか」を説明します。
- 手順の見出しは目的で書きます（「① 保存先を作る」）。本文でも同じラベルを使います。
- 図・表の直前か直後に、それが何を示しているかを 1 文で書きます。

## 5. 確認問題の日本語

- 問いは 1 文で、何を答えればよいかがわかる形にします（「どれでしょう？」「どれを選びますか？」）。
- 選択肢は長さと形をそろえ、文末を統一します（全部「〜から」、全部「〜する」）。
- 誤答の解説（`feedback`）は 2 文以内。1 文目で誤解を言い当て、2 文目で正しい考えを示します。
  例:「画面を作り直しても、データを保存する仕組みは増えません。保存にはバックエンドと
  データベースが必要です。」
- 正解の解説（`explanation`）は、なぜそれが正しいかを本文の言葉で言い直します。

## 6. 英語版（`en`）

- 日本語からの直訳ではなく、同じ内容を自然な英語で書きます。1 段落 80 語以内。
- "simply", "obviously", "just", "easy" で学習者に圧をかけない（`banned-phrase`）。
- 用語は glossary の `en` と一致させます。UI の英語表記はアプリの英語 UI に合わせます。

## 7. してはいけないこと

- 事実・数字・機能・URL・画像パスを作らない。確かめられないことは書かないか、出典を付けます
  （`sources` と `cite`）。
- 学習スタイル（「視覚型の人は」など）を前提にした説明をしない。
- 雑学・宣伝・関係のない統計で導入しない。
- 装飾目的の画像や絵文字を本文に入れない。
- 「こちら」「ここをクリック」だけのリンクにしない。リンク文で行き先がわかるようにします。
