### 公開の文の作り方

- 下書き（`doc/legal/*.draft.ja.md`）を直したら、`node scripts/legal/build-legal-text.mjs` を実行します。`content/legal/*.ja.md` を書き直し、ハッシュと、次に使う版の名前を表示します。
- 見える文が 1 文字でも変わったら、`shared/legal/versions.js` の `version` と `sha256` を、表示されたとおりに変えます（下書きは `terms-draft-2026-10-22.3` のように番号を足します）。新しい `version` と `sha256` の組は、同じファイルの `LEGAL_PINNED_HASHES` にも 1 行足します（消したり書きかえたりはしません。1 つの版の名前は、1 つの文だけを指します）。この 3 つがそろわないと、`npm test`（`server/tests/legalText.test.js`）と `node scripts/legal/build-legal-text.mjs --check` が通りません。古い版の名前のまま `sha256` だけを変えると、その版がすでに入っている DB では同意の記録がすべて 500 `legal_version_conflict` になります。（根拠: …）（作成メモ: …）だけの変更なら、見える文は変わらないので、版はそのままです。
- 確かめるだけなら `node scripts/legal/build-legal-text.mjs --check`（何も書きません）。公開できる状態かは `node scripts/legal/check-legal-release.mjs` で確かめます（残っている印を一覧にします）。
- 開発用のサーバー（`npm run dev`）では、`/terms` と `/privacy` に下書きの文が、残っている印の数の帯つきで出ます。手元でビルドしたものに下書きを入れて見たいときだけ、`NODE_ENV=development LEGAL_DRAFT_PREVIEW_BUILD=true npx vite build --outDir <一時フォルダ>` でビルドし、`npx vite preview --outDir <一時フォルダ>` で開きます（`NODE_ENV=development` のビルドは、`LEGAL_DRAFT_PREVIEW_BUILD=true` がないと止まります）。このビルドはデプロイしません。`npm run build:prod` に `LEGAL_DRAFT_PREVIEW_BUILD=true` を付けても、下書きは入りません。

## オーナーが書き入れること（【要記入】）

1. 法人名、住所、代表者の氏名、問い合わせ先（メールアドレスまたはフォーム、電話番号）。両方の下書きにあります。架空の値は入れないでください。
2. 保護者がアカウントを登録する年齢の線（例: 15 歳以下）。下の「年齢の方針」を見てください。
3. 紙の同意書の様式、受け取った紙の保管場所・保管期間・捨て方（[安全の運用ガイド](../guides/safety-operations.ja.md) の 6 章）。拠点ごとの緊急時の連絡先（同 7 章）。
4. データの保存期間（アカウント削除のとき、最後の利用から何年、など）。
5. 個人情報の責任者、問い合わせの受付時間、開示請求の手数料。
6. ほかに情報を使う目的があれば（寄付者や助成元への報告など）。
7. 争いが起きたときの裁判所。
8. 制定日と改定日。
9. 有料プランを売り始める前に: 「特定商取引法に基づく表記」の販売事業者の情報（登記上の名称、代表者または通信販売の責任者、所在地、つながる電話番号と受付時間、メールアドレス）。`server/services/billingDisclosure.js` の `OWNER_FACTS` にあり、今は【要記入】です。コードの変更なので、プルリクエストで直します。【要記入】が残っているあいだは、本番では売れない作りです。お支払いの記録を残す期間（プライバシーポリシーの下書きの 8）も決めます。

## 公開の前に必要なこと

### 1. 専門家の確認

- 2 つの下書きを、弁護士など個人情報と消費者契約にくわしい専門家に見てもらいます。
- 特に見てもらう点（【要確認】の主なもの）:
  - 外国の会社にデータを送る手続き（個人情報保護法 第 28 条）を、登録時の同意で行うか、相手との契約（相当措置）で行うか。
  - Vercel・Cloudflare・Google Cloud が「預かるだけ」で、第三者提供にも委託にもあたらないと言えるか（個人情報保護委員会 Q&A 7-53 <https://www.ppc.go.jp/all_faq_index/faq1-q7-53/>）。各社の契約（DPA）の確認が要ります。
  - 生活の記録の体調メモが「要配慮個人情報」になる場合の同意の取り方（個人情報保護法 第 20 条第 2 項）。
  - ログイン用の Supabase プロジェクトを Nexloom と共有していることの扱い（`doc/phases/phase18_user_registration_spec.md:54`）。
  - 利用規約の責任の範囲の書き方（消費者契約法 第 8 条・第 10 条 <https://laws.e-gov.go.jp/law/412AC0000000061>）。
  - Google Fonts の読み込みが、電気通信事業法の「外部送信規律」の対象になるか（<https://www.soumu.go.jp/main_sosiki/joho_tsusin/d_syohi/gaibusoushin_kiritsu.html>）。

### 2. 年齢の方針

オーナーの方針は「未成年も、保護者の同意があれば使える」です。

- 日本では 18 歳で成年です（民法 第 4 条 <https://laws.e-gov.go.jp/law/129AC0000000089>）。
- 個人情報保護委員会は、子ども本人の同意について「一般的には 12 歳から 15 歳までの年齢以下の子どもについて、法定代理人等から同意を得る必要がある」としています（Q&A 1-62 <https://www.ppc.go.jp/all_faq_index/faq1-q1-62/>）。
- 子ども食堂の拠点で使われています（`doc/guides/investor_brief.md:56`）。P-School は子ども向けのゲームです。

**Phase 0.5 で実装したこと**（オーナーが「おすすめの既定で進める」と承認。変えられる既定です。[../brushup-2026/ai-access-plan.ja.md](../brushup-2026/ai-access-plan.ja.md) の 4 章）:

- AI を使う前に、生まれた**年と月**を登録します（本人が 1 回。直すのは保護者の申告かスタッフ）。日本時間で年齢を計算し、誕生日は生まれた月の最後の日とみなします。
- 18 歳未満は全員、AI 機能について保護者の同意を記録するまで AI を使えません。同意は、学習者の端末の画面か、紙の同意書（スタッフが記録）で取ります。保護者の名前は記録しません。同意文の版は `guardian-ai-2026-10` です。
- 年齢は申告で、身分証では確かめていません。

まだ決めること: 保護者が**アカウントを登録する**年齢の線（例: 15 歳以下。今は、その年齢でも本人がアカウントを作れます）、年齢を確かめる方法を強めるかどうか。

なお、Anthropic の未成年向けの指針は、保護者の同意や特定の年齢の線を求めてはいません（2026-10-22 に記事を確認）。保護者の同意は、上の個人情報保護委員会の考え方と、オーナーの方針によるものです。

### 3. 未成年が AI 機能を使うための安全対策（Anthropic の要件）

Anthropic の利用ポリシーは、18 歳未満を未成年とし、未成年が使う製品にはサポート記事の追加の指針に従うよう求めています（<https://www.anthropic.com/legal/aup>。ページの表示は「Effective Nov 12, 2026」）。そのサポート記事（<https://support.claude.com/en/articles/9307344-responsible-use-of-anthropic-s-models-guidelines-for-organizations-serving-minors>）が挙げる内容と、Phase 0.5 での対応は次のとおりです。

| 記事の項目 | Phase 0.5 での対応 |
|---|---|
| 年齢の確認（想定した利用者だけが使えるようにする） | AI を使う前に生まれた年と月を登録（申告）。ゲストの AI は既定で止める |
| 不適切な内容のフィルター | 18 歳未満の入力と答えを、サーバーの簡単なチェックと Claude で確かめる。子ども向けの指示を足す。確かめられないときは止める |
| 問題を見つけて対応するための、見守りと報告の仕組み | 止めた件数の記録（文章なし）、報告ボタン、管理者の安全のページ、運営への通知、くり返したときのその日のお休み |
| 未成年が安全に使うための案内 | 公開ページ `/ai-safety`（子ども向け・保護者向けの説明と相談窓口） |
| **利用者に、人ではなく AI と話していることを伝える**（必須） | AI の答えの近くに「AI が作った答えです」と表示 |
| 子どもの安全と個人情報の法律を守り、そのことをサイトなどで公表する | `/ai-safety` の「法令と指針について」。プライバシーポリシーと利用規約のページ（`/privacy`、`/terms`）は作りましたが、公開するまでは「準備中」と出します（下の「ページを公開する手順」） |

記事は、違反が多く対策もしていない組織には、対策を求めることがあるとしています。求められたのに対策をしない場合、または違反が多い状態が続く場合、アカウントの停止や解約につながることがあるとしています。

## ページを公開する手順

1. **`VITE_FEATURE_LEGAL_PAGES=true` にするまで、一般の登録は受け付けません（拠点とテスターだけ）。** 止めているあいだは、登録画面に利用目的のお知らせも同意のチェックもなく、`/privacy` も「準備中」です。個人情報保護法 第 21 条第 2 項の「明示」と、利用規約 第 1 条の同意がない状態なので、一般の方を登録させないでください。自動の確かめはありません（VM からは Vercel の設定が見えないため）。オーナーが守る手順です。
2. 専門家（弁護士）の確認を受けます（上の「1. 専門家の確認」と、下の「弁護士に確かめること（Phase 4）」）。
3. 【要記入】を書き入れます。問い合わせ先（【要記入: 連絡先】）は、Vercel の `VITE_SUPPORT_CONTACT` と同じ窓口にします（アプリの「お問い合わせ」はこれを出します。設定していないと「ご利用の拠点のスタッフにお伝えください」と出ます）。【要確認】をすべて解決し、作成メモと根拠の段落の扱いを決めます。
4. `shared/legal/versions.js` の文書ごとに、`version`（公開の版は `terms-<効力が生じる日>`、例 `terms-2026-12-01`）、`effectiveDate`、`include`、`requiresAcceptance`（最初に公開する利用規約は `true`）を決めます。
5. `node scripts/legal/build-legal-text.mjs` で公開の文を作り、表示された `sha256` を入れ、`node scripts/legal/build-legal-text.mjs --archive` で版の控えを `content/legal/archive/` に作ります。`node scripts/legal/check-legal-release.mjs` が何も出さなくなるまで直します。
6. プルリクエストでマージします。Vercel が、すぐに画面（フロント）を作り直します。
7. **同じ日に** `deploy-stack.sh` を実行して、API を新しくします。しばらくは新しい画面が古い API と動きますが、そのあいだ同意のページは出ません（止まることはありません）。
8. **`VITE_FEATURE_LEGAL_PAGES=true` にする前に、ご本人の削除を使えるようにします。** 利用規約 第 10 条 3 とプライバシーポリシー 9 の 4 は、設定の「アカウントを削除する」から削除できる前提で書いています。ご本人の削除は、はじめ止まっています（API の `ACCOUNT_DELETION_ENABLED` が未設定）。[../brushup-2026/ai-access-plan.ja.md](../brushup-2026/ai-access-plan.ja.md) の 8.2 の 2 と 3 を済ませてから、VM の `stack.env` に `ACCOUNT_DELETION_ENABLED=true` を書き、`deploy-stack.sh` を実行し直します。設定の「アカウントを削除する」を開き、「いまはこの画面から削除できません」が出ないことを確かめます（[../guides/account-deletion-operations.ja.md](../guides/account-deletion-operations.ja.md) の 7 章）。止めたまま公開すると、規約が、使えない機能を約束することになります。止めたまま公開するときは、先に第 10 条 3 と 9 の 4 を、連絡先からスタッフが消す書き方に直し、版を新しくします（上の「公開の文の作り方」）。これも自動の確かめはありません（画面のビルドからは API の設定が見えないため）。
9. Vercel で `VITE_FEATURE_LEGAL_PAGES=true` にして、Redeploy します。文に印が残っていると、ビルドが止まります（`vite.config.ts` の `legal-release-guard`）。
10. 有料プランを始めるときは、`BILLING_TOS_URL` と Stripe の Public details（上の「有料プランを始める前に」）。
11. API とリモートの MCP でも同意を確かめるときは（Phase 8。下の「弁護士に確かめること（Phase 4）」の答えを待ちます）、9 のあと、同意の画面が出ることを確かめてから入れます。`byoa` を使っているなら、先に `deploy/risepath-vm/sql/mcp_remote_role.sql` を流し直します（同意の記録を読む権限が増えます）。そのあと、VM の `stack.env` と `mcp-public.env` に `LEGAL_TERMS_REQUIRED=true` を書き、`deploy-stack.sh` を実行し直します。サーバーからは Vercel の設定が見えないので、この順番はオーナーが守ります。画面のフラグが止まったまま入れると、同意する画面がないまま断られます。止めるときは逆の順番です（`LEGAL_TERMS_REQUIRED` を先に）。文面が案のあいだは、本番の API とリモートの MCP は、この切り替えを無視して、起動時のログに出します。

公開のあとの動き: 登録画面に利用目的のお知らせ（`/privacy#section-3` への 1 クリック）と、外れた状態のチェックが出ます。前からのアカウントには、アプリを開いたときに同意のページが出ます。同意しなくても、保護者の AI の同意の取り消し、記録の削除、AI アプリの解除、プランの解約（`/settings/plan`）、アカウントの削除は、いつでもできます（`App.tsx` の `LEGAL_GATE_EXEMPT`）。同意は画面で求めます。API とリモートの MCP で同意のない方を断る切り替え（`LEGAL_TERMS_REQUIRED`。Phase 8）は、はじめは止めています（上の 11 と、下の「弁護士に確かめること（Phase 4）」）。入れると、同意するまで、ほかの操作（XP・復習・AI の機能など）と、つないだ AI アプリからの呼び出しを断ります。上の操作と、同意のページを読むこと・同意すること、ログアウト（その前の記録の保存）、自分のレッスンの記録を送ることは、入れても断りません（`server/middleware/termsGate.js` の `TERMS_EXEMPT`）。止めているあいだは、同意していない方がつないだ AI アプリも、そのまま動きます（同意のページは、その方が次に Rise Path を開いたときに出ます）。

## 改定するとき

- `requiresAcceptance: true` にするのは、あらためて同意をお願いする変更（重要な変更）のときだけです。その版にすると、アプリを開いた方に同意のページが出ます。
- 上の 11 の切り替え（`LEGAL_TERMS_REQUIRED=true`）を入れているときに `requiresAcceptance: true` の版を出すなら、先に切り替えを止めます。VM の `stack.env` と `mcp-public.env` で止めて `deploy-stack.sh` を実行し直してから、新しい文をマージし、同じ日に `deploy-stack.sh` で API も新しくします（上の「ページを公開する手順」の 5〜7）。同意のページが出ることを確かめてから、切り替えを入れ直します。止めずに出すと、画面（Vercel）と API の版がそろうまで、同意のページは出ないのに、API が呼び出しを断ります。前の版の画面を開いたままの方も、読み込み直すまで同じです。
- それ以外の変更（プライバシーポリシーの変更、言い回しの変更、【要記入】を埋めただけ）は `false` にします。アプリの上に「…を改定しました（○年○月○日から）」のお知らせが出ます。閉じると、その端末では、その版のお知らせは出ません。
- 古い版の項目は `LEGAL_HISTORY` に移し（足すだけ。消しません）、`content/legal/archive/<古い版>.ja.md` を残します。
- 効力が生じる日より前に、新しい文を見せるお知らせ（民法 第 548 条の 4、利用規約 第 12 条 2）は、まだ作っていません。その間は、あらためて同意をお願いする版にするか、新しい文を手でお知らせします。
- 保護者の AI 同意の文を変えるときは、`CONSENT_POLICY_VERSION`（`server/safety/access.js` と `services/aiAccessRules.ts`）を新しくし、`content/legal/archive/<新しい版>.ja.md` とハッシュを `CONSENT_TEXTS` に足します（`server/tests/guardianConsentArchive.test.js` が確かめます）。

## 弁護士に確かめること（Phase 4）

- [ ] 同意の記録・保護者の同意の記録・削除の記録を、アカウントを削除したあと 5 年残すこと（オーナーの決定 D5）と、プライバシーポリシー 8 の書き方。同意の時刻を、チェックを入れた時ではなく、最初にログインしてサーバーに届いた時にしてよいか。プライバシーポリシーにも別のチェックが要るか。
- [ ] 定型約款（民法 第 548 条の 2〜4）: 無料の登録が定型取引にあたるか。ページとチェックで足りるか。どの変更であらためて同意をお願いするか（`requiresAcceptance`）、ほかの変更はお知らせの帯で足りるか。利用目的の変更の扱い。
- [ ] 同意は画面で求め、API とリモートの MCP は、切り替え（`LEGAL_TERMS_REQUIRED`。はじめは止めています）を入れるまで止めないこと（止めているあいだは、同意していない方がつないだ AI アプリも、そのまま動きます。同意のページは、その方が次に Rise Path を開いたときに出ます）。入れる場合、断らない操作の一覧（`server/middleware/termsGate.js` の `TERMS_EXEMPT`。自分のレッスンの記録を送ること、ログアウトの前の保存を含みます）でよいか。
- [ ] AI アプリをつなぐことが第三者提供（個人情報保護法 第 29 条）にあたるか。あたるなら、AI アプリの記録（3 年）がその記録です。あたらないなら、その記録をやめます。
- [ ] アカウントを削除した日の AI の利用回数を、不正利用の防止のため 30 日残すこと。
- [ ] 外国への提供の手続き（第 28 条）を、登録のときの同意（a）にするか、契約（b）にするか。（a）なら、施行規則 第 17 条の項目をチェックの上に出し、別の版を記録します（今は作っていません）。
- [ ] 未成年: 保護者がアカウントを登録する年齢の線、保護者の同意を記録するか、保護者なしに未成年が削除できること（今は止めません）、2026 年の改正（施行されたら）。
- [ ] 文書が日本語だけで、英語の画面にはそのお知らせだけを出すこと。削除の確認が画面だけ（メールを送らない）であること。
- [ ] 保護者の AI 同意の文の控え（`content/legal/archive/guardian-ai-2026-10.ja.md`）は、`82a5ded` の画面の文から作りました。`guardian-ai-2026-10` を使い始めた時から同じ文だったか、git の履歴で確かめてください。

- [ ] Phase 5: XP・バッジ・学んだ日を数えてサーバーに保存すること（18 歳未満の方の分もふくむ）と、XP と学んだ日の記録を始める前の、レッスンを始めた・終えた記録とレッスンの進み具合の日付から学んだ日を作ることが、プライバシーポリシー 3 の 1 の「記録の表示」の範囲か。範囲の外なら目的の変更なので、`requiresAcceptance` とお知らせの形を変えます（今は範囲の中として、版を上げただけです。`privacy-draft-2026-10-22.5`）。
