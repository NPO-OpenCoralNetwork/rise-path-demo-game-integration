# レッスンに「ステップ図」を足す計画

- 日付: 2026-11-18
- 状態: 試作の形と 3 章の考え方は、2026-11-18 にオーナーが了承しました。2 章の D1〜D6 は、同じ日に、オーナーがおすすめのとおりに決めました。5 章の 1 段目（仕組みと表示）から作ります。
- 関連: [PLAN.ja.md](PLAN.ja.md)（ブロックの一覧、WP-05）、[../design/design-system.md](../design/design-system.md)（色と動きの決まり）、`.claude/skills/author-lesson/`（教材を書くスキル）、[training-plan.ja.md](training-plan.ja.md) 4.4（職業訓練の教材も同じ形式を使う）

いまのレッスンの図は、mermaid（文字で書く図）だけです。`content/` の 26 ファイル（見本と下書きを含む）に 30 個あり、流れ図が 22、シーケンス図が 4、マインドマップが 4 です。mermaid の図は、できあがった形を 1 枚で見せます。「何が、どの順に、どう変わるか」を教える図では、読む人が矢印を自分でたどることになります。

この計画は、**同じ 1 枚の図が、ステップごとに少しずつ変わる図**を、レッスンの形式に足します。この文書では「ステップ図」と呼びます。学ぶ人が「次へ」を押すと、図の一部が動き、その下の文章が替わります。

考え方は、公開されている教材サイト（<https://designed-to-scale.vercel.app/>）を参考にしました。コード・絵・文章は使いません。見た目は Rise Path のものにします。形は、リポジトリの外で作った試作（1 ページ）で確かめました。

この文書の規模（M・L）は、どれも**見積もり**です。

## 1. 作るもの

| もの | 中身 |
|---|---|
| 新しいブロック `stepFigure` | ステップごとの文章と、図の状態を持つデータ。コードは持たない（4.1） |
| 絵の型 `flow` | 部品（画面・箱・保管庫）と、そのあいだを流れる印を描く仕組み。教材を書く人は、データだけ書く（4.2） |
| 枠 | 図の下の操作（戻る・次へ・もう一度・進み具合の線）と、ステップの文章。どのステップ図でも同じ（4.3） |
| 検査 | 形式の検査（参照の間違いなど）と lint（ステップの数、文の長さ、ラベルが収まるか）（4.4） |
| スキルへの追加 | `author-lesson` に、いつ使うか・ステップの切り方・確かめ方を足す（4.7） |
| プレビュー | `lessons:preview` が、各ステップの終わりの状態を画像にする（4.7） |

最初に置き換える図は、バイブコーディング第 1 章の下書き（`content/courses/vibe-coding/drafts/vibe-ch1.lesson.json`）の図 1 つです。いまは「ユーザー → フロントエンド ⇄ バックエンド ⇄ データベース」の流れ図です。ステップ図では、レッスンの冒頭の話（タスクを再読み込みすると消える）を、次の 7 ステップで見せます。

1. 画面だけのアプリで、タスクを追加する
2. 再読み込みすると、消える
3. 足りなかったバックエンドとデータベースが現れる
4. 追加すると、バックエンドに依頼が届く
5. 確かめて保存し、返事が戻る
6. 再読み込みしても、残っている
7. まとめ（いまの流れ図と同じ絵になる）

| D6 | 作る順番 | 先に仕組みと表示だけを作り、開発用の画面で見た目を確かめてから、形式に足す（5 章） | 形式は、一度公開すると変えにくい。実物の見た目と、スマホでのラベルの収まりを先に確かめる |

## 3. 考え方

1. **見た目と動きは、コードで決めます。** スキルの文章では決めません。試作では、スマホでの文字の大きさ、操作の並び、自動再生の不具合を直しました。どれも仕組みの側の直しです。仕組みを 1 つにしておけば、どの図にも同じ直しが効きます。教材を書くたびにコードから書くと、図ごとに見た目がばらつき、同じ不具合がまた出ます。
2. **枠と絵を分けます。** 枠は、操作と文章です。絵は、その上の図の部分です。枠を共通にしておけば、絵の種類が増えても、使い方は変わりません。
3. **絵は 3 段で考えます。**

   | 段 | 中身 | 向くもの |
   |---|---|---|
   | 型 | 仕組みは固定で、教材にはデータだけ書く（この計画の `flow`） | 部品のあいだを何かが流れる話、状態が変わる話。ほとんどの図 |
   | 登録した図 | その図のためのコードをリポジトリに置き、教材からは名前で呼ぶ（4.8） | 型に合わない 1 回きりの図。回して見るような本当の 3D |
   | 動画 | レッスンの外で作る MP4 | 演出の強い動き |

4. **先に「何を見せるか」を決めます。** 物・画面・変化のどれを見せるかを決めてから、手段を選びます。3D は、見せたいもの自体が立体のとき（形・位置・向き）だけにします。参考にしたサイトの「立体に見える絵」は、平面の絵の描き方です。型のまま、描き方だけ変えれば出せます。
5. **コードは、教材の中に書きません。** 教材は、AI アプリからも届くデータです（MCP の `lesson-upsert-draft`）。教材の中にコードを書けるようにすると、危ない教材を作れてしまいます。mermaid の図が、設定の書き込みを取り除き、できた SVG を消毒してから表示しているのと同じ理由です（`components/lesson/blocks/mermaidRenderer.ts`）。
6. **同じものが 3 回要ったら、型にします。** 最初から型を増やしません。型に合わなかった図を記録し、繰り返し出てきたものだけを型にします。

## 4. 作り方

### 4.1 データの形

ブロックの例です（第 1 章の図の一部。ステップは 1 つだけ載せています）。

```json
{
  "id": "s1-fig",
  "type": "stepFigure",
  "caption": "タスクが消えるわけと、残るようにするしくみ",
  "alt": "ブラウザの画面、サーバー、データベースの 3 つの部品の図。ステップごとに、タスクのデータがどこを通り、どこに残るかが変わる。",
  "picture": {
    "kind": "flow",
    "layout": "side-stack",
    "parts": [
      { "id": "front", "shape": "screen", "slot": "main", "label": "フロントエンド",
        "app": { "title": "タスク", "action": "追加", "empty": "タスクはありません" } },
      { "id": "back", "shape": "box", "slot": "top", "label": "バックエンド", "sub": "サーバー" },
      { "id": "db", "shape": "store", "slot": "bottom", "label": "データベース", "empty": "0 件" }
    ],
    "links": [
      { "id": "api", "from": "front", "to": "back" },
      { "id": "save", "from": "back", "to": "db" }
    ],
    "actor": { "at": "front", "label": "あなた", "verb": "操作する" },
    "carriers": { "data": "データを運ぶ", "ask": "頼むだけ" }
  },
  "steps": [
    {
      "id": "s1-fig-ask",
      "kind": "how",
      "title": "追加すると、バックエンドに依頼が届く",
      "body": "もう一度、追加します。フロントエンドはタスクのデータを添えて、バックエンドに依頼します。",
      "points": [{ "part": "front", "text": "画面の一覧は、まだ変わらない" }],
      "scene": {
        "parts": [
          { "part": "front", "field": "牛乳を買う" },
          { "part": "back" },
          { "part": "db" }
        ],
        "links": [
          { "link": "api", "show": "idle" },
          { "link": "save", "show": "idle" }
        ]
      },
      "play": [
        { "do": "tap", "part": "front",
          "then": { "parts": [{ "part": "front", "pressed": true }] } },
        { "do": "send", "link": "api", "dir": "forth", "carry": "data", "label": "依頼",
          "then": { "parts": [{ "part": "back", "busy": true }] } }
      ]
    }
  ]
}
```

| 欄 | 中身 |
|---|---|
| `id`・`cite` など | ほかのブロックと同じ共通の欄（`blockBase`）。図に書いたことの出典は、`cite` で示す |
| `caption`・`alt` | 必須。`caption` は「図 n」の後ろに出る。`alt` は、図全体を 1〜2 文で言い表す |
| `picture.kind` | 絵の型。最初は `flow` だけ |
| `picture.layout` | 部品の置き方（4.2） |
| `picture.parts` | 部品の一覧。`id`、形（`shape`）、置く場所（`slot`）、名前（`label`）と、形ごとの決まった文字 |
| `picture.links` | 部品をつなぐ線。`from` から `to` の向きを「行き」とする |
| `picture.actor` | 「あなた」の印（なくてもよい） |
| `picture.carriers` | 流れる印の説明（図の下の凡例に出る。書かなければ、決まった文が出る） |
| `steps[].id` | ステップの id。レッスンの中で重ならない（進み具合・リンク・レビューのコメントが id を使うため） |
| `steps[].kind` | `problem`（問題）・`how`（しくみ）・`solution`（解決）・`recap`（まとめ）。なくてもよい |
| `steps[].title`・`body`・`points` | ステップの文章。`body` は 2 文まで。`points` は 3 つまでの短い箇条書きで、`part` を書くと、どの部品の話かを示す小さな印が付く |
| `steps[].scene` | そのステップが**始まるとき**の図の状態。書いた部品と線だけが見える。書かなかったものは見えない |
| `steps[].play` | 起きることを、順に並べる。それぞれ、終わったときに状態を変えられる（`then`） |

- 文字の欄は、ほかのブロックと同じ `LText`（`body` は `Md`）です。ラベルの中では、マークダウンを使えません。
- 部品と線の状態は、id をキーにした入れ物ではなく、並びで書きます（`{ "part": "front", … }`）。AI 向けの形式（`content/schema/lesson.llm.schema.json`）は、決まっていないキーを持つ入れ物を表せないからです（`shared/lesson/jsonSchema.js` の `toLlmSchema`）。
- ステップごとに、状態を全部書きます。前のステップとの差だけを書く形にはしません。1 つのステップのデータだけを読めば、そのとき図に何が出ているかが分かり、レビューしやすいからです。前のステップの終わりと食い違っていないかは、プレビュー（4.7）で確かめます。
- 形式の側で、数に上限を付けます（ステップ 12、部品 6、1 ステップの動き 8、待ち時間 1.5 秒）。教材は外からも届くので、表示する側が困る大きさを受け取らないためです。読みやすさのための目安（もっと小さい数）は、lint で見ます（4.4）。

### 4.2 絵の型 `flow`

**部品の形**

| `shape` | 絵 | 決まった文字 | ステップごとの状態 |
|---|---|---|---|
| `screen` | ブラウザの窓と、その中の小さなアプリ | `app.title`（アプリの名前）、`app.action`（ボタンの文字）、`app.empty`（一覧が空のときの文字） | `field`（入力欄の文字）、`pressed`（ボタンを押した）、`items`（一覧の行） |
| `box` | 角の丸い箱 | `sub`（2 行目の文字） | `busy`（処理中）、`sub`（2 行目を替える。例: 確かめ中…） |
| `store` | 円柱（データをしまう場所） | `empty`（空のときの文字） | `items`（しまってある行） |

どの部品にも、`show` があります。`on`（既定）は普通に見せ、`ghost` は点線の枠と「？」だけを見せます（「ここに何かが足りない」と示すために使います）。`off` は、`then` で部品を隠すときに使います。

線の状態は、`show`（`idle` 点線・`forth` 行きの矢印・`back` 帰りの矢印・`both` 両方）と、ラベル（`label`。`both` のときの帰りのラベルは `backLabel`）です。

**置き方**

絵は、横 360 × 縦 272 の座標で描きます。スマホでは、ほぼそのままの大きさになります。図の中の文字は、いまの図と同じく、13px を下回らないようにします。とても幅の狭い画面では、絵を横にスクロールできるようにします。広い画面でも、絵は 480px より大きくしません。

| `layout` | 置く場所（`slot`） | 線を引ける組 | 状態 |
|---|---|---|---|
| `side-stack` | `main`（左の大きな場所）、`top`・`bottom`（右に 2 段） | `main`–`top`、`top`–`bottom` | 試作で確かめた |
| `pair` | `left`・`right`（左右に 1 つずつ。中に 3 行まで入る） | `left`–`right` | 寸法は仮。使う教材と一緒に作る |
| `column`・`ring` | 縦に並べる、輪にする | | まだ作らない。要る教材が出たら足す |

教材には、座標を書きません。置く場所の名前だけを書きます。ラベルが収まる文字数は、置く場所ごとに決まります。下の表は `side-stack` の初期値です（全角 1 文字を 1、半角の英数字を 0.55 と数えます）。

| ラベル | 上限 |
|---|---|
| `main` の部品の名前 | 10 |
| `top`・`bottom` の部品の名前、`sub` | 6 |
| `screen` の `app.title` / `field` / `app.action` / 一覧の 1 行 / `app.empty` | 8 / 5 / 2 / 7 / 9 |
| `screen` の一覧の行数、`store` の行数 | 2、1（1 行は 5 文字まで） |
| `main`–`top` の線のラベル | 4 |
| `top`–`bottom` の線のラベル | 6 |
| `actor` の `label` / `verb` | 3 / 5 |

**起きること（`play`）**

| `do` | 意味 | 欄 |
|---|---|---|
| `tap` | `screen` のボタンを押す | `part` |
| `reload` | `screen` を再読み込みする | `part` |
| `send` | 線の上を、印が流れる。線は、流れた向きの矢印とラベルになる | `link`、`dir`（`forth` 行き・`back` 帰り）、`carry`（`data` データを運ぶ・`ask` 頼むだけ）、`label` |
| `wait` | 少し待つ | `ms`（200〜1500） |

- 動きの速さは、仕組みの側で決めます（押す 0.5 秒、再読み込み 0.8 秒、流れる 0.95 秒、あいだ 0.4 秒）。教材からは変えられません。どの図も同じ間合いになります。
- 1 つのステップの動きは、1 回だけ再生して止まります。流れ続ける動きは作りません。
- 動きは「ステップが始まってからの時間」から決まる計算にします。同じ時間なら、いつも同じ絵になります。テストしやすく、あとで動画の 1 場面として書き出す道も残せます。

### 4.3 枠

上から順に、次のものを置きます。試作と同じです。

1. **絵**。右上に小さな「もう一度」（そのステップを再生し直す）。下に凡例（流れる印の説明）。
2. **進み具合の線**。ステップの数だけ区切った細い線。区切りを押すと、そのステップに飛ぶ。
3. **操作の 1 列**。戻る、「ステップ 3 / 7」とステップの種類（しくみ など）、次へ。最後のステップでは、次へが「最初から」になる。
4. **文章**。ステップの題、本文、箇条書き。

- 自動で動くのは、図が画面に半分以上入ったときの、1 ステップ目の 1 回だけです。学ぶ人が先に操作していたら、自動では動かしません。ステップは、自動では進めません。
- 枠の文字（次へ、ステップ n / N など）は、日本語と英語を持ちます（`const copy = { en, jp }`）。ステップの種類は、文字で出します。色では区別しません。
- 図の番号（図 n）とキャプションは、いまの `diagram` と同じ出し方にします（`components/lesson/blocks/DiagramBlock.tsx`、`components/lesson/model.ts` の `figureNumbers`）。
- 拡大のダイアログは付けません。絵は、はじめからスマホの幅に合わせた大きさです。

### 4.4 検査

**形式の検査（エラー。`shared/lesson/validate.js`）**

- ステップの id を、レッスンの id の名前空間に入れる（重なったらエラー）。部品と線の id は、その図の中だけで重ならなければよい。
- `slot` が、その `layout` にある。1 つの場所に、部品は 1 つ。
- 線は、宣言した部品どうしをつなぎ、その置き方で引ける組である。
- `scene`・`play`・`then`・`points[].part` が指す部品と線が、宣言されている。1 つの `scene` に、同じ部品・同じ線を 2 回書いていない。
- 形に合わない欄を書いていない（`field` は `screen` だけ、など）。`tap`・`reload` の相手は `screen` である。
- `send` は、両端の部品が見えているときだけ。
- どの文字の欄にも、レッスンが宣言したすべての言語がある（いまの検査が、`shared/lesson/walk.js` に足した欄を見る）。

**lint（警告。`--strict` で失敗。`shared/lesson/lint.js`）**

| ルール | 中身 |
|---|---|
| `stepfigure-steps` | ステップは 3〜8 |
| `stepfigure-parts` | 部品は 2〜5。どの部品も、どこかのステップで見える |
| `stepfigure-text` | 題は 20 文字まで。本文は 2 文まで。箇条書きは 3 つまで、1 つ 24 文字まで（英語は語数で数える） |
| `stepfigure-label-fit` | ラベルが、置く場所の上限に収まる（4.2 の表） |
| `stepfigure-play` | 1 ステップの動きは 5 つまで、合わせて 8 秒まで |
| `stepfigure-no-change` | 前のステップの終わりと、何も変わらないステップがない |
| `stepfigure-recap` | 最後のステップは `recap` で、全部の部品が見える |

いまの `sentence-length`（1 文 60 文字）・`paragraph-length`・`banned-phrase`・`locale-plain-string` は、ステップの文章にもそのまま効きます。

「1 つのステップに考えを 1 つ」「絵と文章が合っている」は、lint では見られません。レビューで見ます（4.7）。

### 4.5 表示

- **色**: トークンだけを使います（`styles/tokens.css`）。部品は、面と枠線と文字の色（`surface`・`border-strong`・`fg` など）で描き、形と名前で見分けます。講座のアクセント色（`--world-accent-*`）は、いま動いているもの（押したボタン、流れる印、使った線）と、いま変わったもの（足された行）に使います。操作は、ほかの画面と同じ操作の色（`primary`）にします。色は CSS の変数で付けるので、明るい・暗い・セピアの表示に、描き直しなしで合います。
- **動き**: 長さとイージングは、いまのトークンを使います（120ms・200ms・320ms、`--rp-ease`）。`prefers-reduced-motion` のときは、印を流さず、各ステップの終わりの状態を出します。「もう一度」は出しません。
- **読み上げとキーボード**:
  - 絵は `role="img"` と `alt`。ステップの文章は、替わったことが読み上げソフトに伝わる場所（`aria-live`）に置く。
  - 操作は、すべて本物のボタン。図の中にフォーカスがあるあいだは、← → でも進める。
  - 「図の説明を読む」（いまの `diagram` と同じ折りたたみ）を付け、全部のステップの題と本文を、番号付きの一覧で出す。この一覧は、ステップのデータから自動で作る。
- **小さい画面**: 絵は、カードの幅いっぱいに描きます。操作は絵のすぐ下に置き、文章はその下に置きます。文章の長さが変わっても、操作の位置は動きません。
- **スクロール**: アプリは `<main id="main-content">` の中でスクロールします。図が画面に入ったかどうかは、その入れ物を基準に見ます（`components/lesson/useScrollContainer.ts`）。
- **失敗したとき**: 絵を描けなかったら、`alt` と、全部のステップの一覧を出します。本番のアプリは、教材を検査せずに読み込みます（検査は開発のときと CI）。表示する側でも、欠けたデータで止まらないようにします。
- **重さ**: 新しいライブラリは足しません。SVG と、いまある React だけで作ります。動きのための JavaScript のライブラリ（GSAP など）は、いまも入っていません。動いているあいだだけ、描き直します。

### 4.7 スキル・レビュー・プレビュー

- **手引き**: `.claude/skills/author-lesson/references/block-cookbook.md` は、見本の教材・形式・lint の決まりと、スクリプトの中の種類ごとの説明から作られます。見本の教材に、よい例を 1 つ足します。
- **スキルの本文**（`SKILL.md`）に足すこと:
  - いつ使うか: 順番や変化を見せたいときだけ。全体の形を 1 枚で見せたいときは `diagram`、比べたいときは `table`。
  - 書く順番: 先に、ステップの文（題と本文）だけを並べて書く。1 つのステップに、考えは 1 つ。最後のステップは、全体をまとめた絵にする。そのあとで、図の状態と動きを書く。
  - 確かめ方: プレビューが出した、各ステップの画像を全部開いて見る。
- **プレビュー**（`scripts/lessons/preview.mjs`）: いまは、動きを減らす設定で画面を撮ります（Playwright）。この設定では、ステップ図は各ステップの終わりの状態を出すので、そのまま撮れます。ステップ図ごとに、各ステップを 1 枚ずつ画像にします（スマホの幅、日本語）。`metrics.json` に、ステップごとの「前のステップから変わったこと」の一覧と、枠からはみ出したラベルの一覧を書きます。はみ出しと、描けなかった図は、mermaid のエラーと同じく、失敗として数えます。
- **レビュー**: `visual-qa` は、各ステップの画像で、文字の重なりとはみ出しを見ます。`pedagogy-reviewer` は、1 ステップ 1 つの考えになっているか、絵と文章が合っているか、動きが飾りになっていないかを見ます。評価の基準（`content/schema/rubric.v1.json`）に、この見方を足します。

### 4.8 登録した図（設計だけ）

型に合わない図は、次の形で足せるようにしておきます。D4 のとおり、いまは作りません。

- 教材には、`"picture": { "kind": "registered", "name": "<名前>" }` と、ステップごとの `"show": "<状態の名前>"` を書きます。枠（操作と文章）は、ステップ図と同じです。
- 絵のコードは、リポジトリに置きます。プルリクエストでレビューします。教材からは、名前でしか呼べません。
- 名前と、その図が持つ状態の一覧を、zod を使わない共有のファイルに登録します。形式の検査は、その一覧で、名前と状態の間違いを見つけます。
- 絵のコードが守ること: 渡された状態と時間から絵を描く。動きを減らす設定に従う。色はトークンを使う。外と通信しない。描けない端末のために、代わりの絵か文章を持つ。重いライブラリ（3D など）は、その図が画面に入ってから読み込む。
- 同じ種類の図が 3 回要ったら、型にします（3 章の 6）。

## 5. 順番

| 段 | 中身 | 規模 |
|---|---|---|
| 1 | **仕組みと表示**。動きと状態の計算（zod を使わない共有のファイル）とそのテスト。枠と `flow`（`side-stack`）の表示。開発用の画面（`/dev/blocks?dev=1`）で、試しのデータを見せる。レッスンの形式は変えない | L |
| 2 | **形式に足す**。4.6 の表のうち、形式・検査・lint・文章の取り出し・見本・手引きを変える | L |
| 3 | **プレビューとレビュー**。各ステップの画像、レビューの見方、スキルの本文 | M |
| 4 | **最初の教材**。第 1 章の下書きの図を置き換える。`/author-lesson` の作り直しとして進め、レビューを通す | M |
| そのあと | `pair` と、それを使う教材。型に合わない図が出てきたら、登録した図 | |

- 1 段目のあとで、オーナーが実物の見た目を見ます。D2（色）は、そこで見直せます。
- 公開中の教材の図を置き換えると、その教材のレビューの記録（`lessonHash`）が古くなります。置き換えは、教材ごとに、作り直しとレビューの手順で進めます。まとめては置き換えません。

## 6. 受け入れているリスク

- **仕組みが大きくなる。** 部品の形や置き方を、求められるたびに足すと、手入れが重くなります。足すのは、それを使う教材と一緒のときだけにします。
- **図があっても、分かりやすくならないことがある。** ステップの切り方が悪いと、押す回数が増えるだけになります。lint では防げないので、レビューで見ます。
- **スマホでは、置けるものが少ない。** 部品は 5 つまでで、ラベルは短くなります。収まらない話は、図を 2 つに分けるか、`diagram` を使います。
- **英語では、ラベルの幅が変わる。** 上限は、文字の幅の見積もりです。最後は、プレビューの画像で確かめます。
- **AI アプリから、質の低い図の下書きが届く。** 下書きのままでは公開されません。公開の前のレビューは、いまと同じです。

## 7. まだ分からないこと

- スライドの表示での見せ方。スライドの表示は、まだありません（ボタンは「近日公開」のまま。ブロックの `slide`・`narration` の欄は、表示では使っていません）。できるときに、ステップごとに 1 枚にするか、読み上げの文を持たせるかを決めます。
- `pair` の寸法と、ラベルの上限。
- 紙に刷るときの出し方（最後のステップの絵と、全部のステップの一覧にする見込み）。
- このリポジトリに置かない教材（職業訓練の教材）の画像を、どこで撮るか。`lessons:preview` は、このリポジトリにある講座だけを扱います。

## 8. やらないこと

- 教材の中に、コード・HTML・URL を書けるようにすること。
- ステップを自動で進めること、音を付けること。
- いまの `diagram`（mermaid）を変えること。全体の形を 1 枚で見せる図には、これからも `diagram` を使います。
- 30 個の図を、まとめて置き換えること。
- 図を作るための編集画面。
- 同じデータから動画を作ること（道は残しますが、別の計画にします）。
