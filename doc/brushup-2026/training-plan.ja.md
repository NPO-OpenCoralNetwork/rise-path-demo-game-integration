# 職業訓練の LMS の計画

- 日付: 2026-10-28（2026-10-29 にレビューの指摘を反映し、オーナーが D1〜D9 を決めました）
- 状態: 2 章の D1〜D9 は、2026-10-29 にオーナーがおすすめのとおりに決めました（D9 は「公開で作る」）。第 1 段の 1 つ目のプルリクエスト（骨組み）から作ります。
- 関連: [ai-access-plan.ja.md](ai-access-plan.ja.md)（今の Rise Path の決定記録）、`SECURITY.md`（セキュリティの基本の設定。5 章の 1 で先に入れます）

職業訓練（e ラーニング）で使う LMS（受講の管理のしくみ）を、Rise Path の中の**別のセクション**として作る計画です。既存の講座と学習者の動きは変えません。学校は、同じコードの別のデプロイで動かします。

このリポジトリは公開です。この文書には設計だけを書きます。訓練の実施機関とのやりとり、不正を見つけるための設定値、受講者の情報、訓練の不具合（受講時間の数え方の穴など）は、ここにも issue やプルリクエストにも書きません（非公開の計画用リポジトリに置きます）。訓練の不具合を直すプルリクエストには、穴の使い方を書きません。

## 1. 作るもの

| 機能 | 中身 |
|---|---|
| 期と受講者 | 期（クラス）を作り、受講者・講師・確認用のアカウントを割り当てる |
| 受講時間 | 画面からの一定の間隔の合図を、サーバーの時刻で数え、暦日ごとに集計する。本人の申告は使わない |
| 単元の開放と確認テスト | 問題をサーバーに置き、サーバーで採点する。合格したら次の単元を開く。受験ごとに記録する |
| ログインの記録 | ログインとログアウトの時刻を記録する |
| 質問とライブ | 講師への質問欄、ライブの予定と出欠、録画での振替 |
| 記録の書き出し | 受講時間・出欠・成績を CSV で書き出す |
| 監査ログ | 記録を直した人・理由・前後の値を、書き換えずに追記して残す |
| バックアップ | 学校の DB を毎日バックアップし、暗号化して、VM とリポジトリの外の、見られる人を絞った場所に置く。月に 1 回、戻せるかを試す。仕組みは既定でオフにし、学校の VM だけで有効にする（公開版の約束を変えないため） |

受講時間は、単元ごとに定めた時間を上限にして数えます。合図の間隔、操作がないときに止める条件などの値は、実施機関への確認のあとで決めます（7 章）。

## 4. 作り方

### 4.1 置き場所

- 純粋な規則（受講時間の数え方、暦日への割り当て、開放の判定、CSV の行の形）は `shared/training/`。
- DB の処理は `tools/core/training*.js`、HTTP は `server/routes/training*.js`、画面は `components/features/training/`。
- テストは `server/tests/training*.test.js`（`npm test` は `server/tests/` の直下だけを流す）。
- この分け方なら、今の `lint:arch` の層の決まりに合います。新しいトップレベルのフォルダは作りません。

### 4.2 API

- `server.js` には、ルーターの登録と本文の上限を、1 行ずつだけ足します（Phase 8 の作業も同じファイルを変えているため）。本文の上限は、ほかの小さい上限と同じく 2 MB のパーサー（`JSON_BODY_LIMIT`）より前に、ルーターは Phase 2〜6 のルーターと同じく `/api/v2/user` の登録より前に置きます。`/api/v2` の受け皿（`app.use('/api/v2', …)` の並び）より後ろに置くと、AI の回数制限（`aiLimiter`。本番は 1 人 1 分 10 回）が合図にもかかるためです。骨組みのプルリクエストで、この形で入れました（`server/routes/training.js`）。
- XP と復習の API（Phase 5・6）と同じく、`requireAuth` と `requireSignedIn` をかけ、利用者ごとの回数制限を付けます。AI アプリのトークンは断られるので、訓練の API は AI アプリから呼べません。
- 合図は、IP ごとの全体の回数制限（`globalLimiter`。本番は 1 分 200 回）にも数えます。同じアドレスから受講する人数で足りるかと、学校のデプロイで API が見るアドレスが受講者のものかを確かめます（7 章）。
- `TRAINING_ENABLED` がないときは、404 を返します。

### 4.3 表（次の番号の migration。今の main では 021）

- 番号は、入れるときの最新の次にします（先に入れる作業が migration を足せば、021 はそちらが使います）。同じプルリクエストで、`server/migrations/README.md` の表と、`server/tests/deployDocsMigrationRange.test.js` が確かめる 3 つの手順書の「000–NNN」を直します。
- プルリクエストごとに、次の番号の migration を 1 つ足します。どれも `CREATE TABLE IF NOT EXISTS` などで、2 回流せる形にします。
- 期、割り当て、単元、単元の進み、合図、暦日ごとの受講時間、受験、ライブ、出欠、質問、ログインの記録、監査ログの表を作ります。
- `user_id` は持ちますが、`auth.users` への外部キーは張りません。退会の処理（`server/services/accountDeletion.js` のトランザクション）で、規約の同意の証拠と同じく、印（`account_deleted_at`）を付けます。共有の退会の処理を変えるので、文の並びを固定しているテスト（`server/tests/accountDeletionService.test.js`）と、`scripts/delete-account-data.mjs` の `--dry-run` の表の一覧（`DRY_RUN_TABLES`）も、同じ変更で直します。
- 書き込みは、アカウントの共有のロックを取り、`auth.users` の行があるときだけにします（`server/routes/legal.js:61` と同じ）。退会と重なった書き込みが、印のない行として残らないようにするためです。
- 受講者本人への読み出しと、開放などの判定は、印のない行だけで行います（削除のあとに同じ ID で開き直した、空のアカウントにつなげないため）。職員の一覧と CSV の書き出しでは、印のある行も、退会したと分かる形で読みます。一意の制約は、印のない行だけにかけます（018 の `legal_acceptances_live_uniq` と同じ）。
- 暦日は、今の表と同じく日本時間で切ります。
- 監査ログ・受験・ログインの記録は、追記だけにします。直すときは、新しい行を足します。行を変えるのは、退会の処理で印を付けるときだけです（018 の同意の証拠 `legal_acceptances` と同じ）。版の表 `legal_document_versions` の、更新も削除も止めるトリガー（`rp_rows_immutable`）は、そのまま付けません。付けると、印を付ける更新で退会の処理全体が戻り、本人・スタッフ・`--orphans` のどの削除も失敗します。
- AI アプリのロール（`deploy/risepath-vm/sql/mcp_remote_role.sql`）には、何も足しません。最初にすべての権限を外す作りなので、足さなければ読めません。DB の確かめ（`scripts/ci/db-checks.sh`）で、そのことを確かめます。
- migration はどのデプロイにも当たるので、公開版の Rise Path の DB にも空の表ができます。

### 4.4 教材と採点

- 訓練用のカタログ（例: `tools/core/trainingCatalog.js`）を作り、学校の VM の非公開の置き場所か DB から読みます。形式は `risepath.lesson/v1` のままにして、検証の仕組みを使い回します。
- 期に登録していて、単元が開いている受講者にだけ、答えを抜いた形で返します。
- 採点はサーバーで行います。`shared/lesson/grading.js` の答えを比べる関数だけを使い、「2 回目で答えを見せる」規則は使いません。
- 受験ごとに、サーバーの時刻・点数・合否・問題の版を記録します。
- `risepath.lesson/v1` の問題は選択式（`single`・`multi`・`truefalse`）だけで、短い記述の問題は出せません。確認テストは選択式で始めます。記述の問題が要るときは、`shared/lesson/schema.js` は変えずに、訓練用の問題の形と採点のしかた（AI は使いません。D6）を別に決めます。

### 4.5 ログインとログアウトの記録

- 訓練のルートだけにかけるミドルウェアで、セッションごとのログインの時刻（トークンにあるサインインの時刻）を記録します。`requireAuth` は変えません（変えると、訓練の外のすべての利用者の動きが変わるため）。
- ログアウトはサーバーに届きません（サインアウトは、画面から Supabase に直接送られます。`context/AuthContext.tsx:370-385`）。ログアウトのボタンは共有の画面にもあるので、`logout` に、`VITE_FEATURE_TRAINING` がオンのときだけ動くフックを 1 つ足し、サインアウトの前に訓練の API に知らせて、サーバーの時刻で記録します。オフなら今の動きのままです。
- ログアウトの操作がないとき（タブを閉じた、セッションが切れた）の終わりの時刻は、最後の合図の時刻とする案にします（7 章）。
- 同じアカウントで 2 か所目にログインしたとき（新しいセッション）の扱いは、実施機関に確かめてから決めます（7 章）。それまでは古いセッションを断らず、受講時間は D11 のとおり、両方の画面の合図を記録して、同じ瞬間を 1 回だけ数えます。断ることにしたら、そのときの `error_type` は `account_deleted` にしません（画面が、その端末の記録を消してサインアウトするため）。

### 4.6 画面

- `/training/*` に、フラグで切り替える遅延読み込みのルートを 1 つ足します（規約のページと同じ形）。
- `LessonReader` は使いません。本文のブロックの部品の多くは、読み手の文脈（`ReaderContext`）がないと例外を投げます。段落と囲みには「AI先生に聞く」、コードには説明のボタンが付き、どちらも AI 先生を呼びます。使い回すときは、訓練の画面で文脈を用意し、AI 先生のボタンを出さない切り替え（既定は今の動きのまま）を足します。AI 先生に聞くブロック（`askTutor`）は、訓練では出しません。
- テストは専用の部品で、サーバーに採点させます。

### 4.7 学校のデプロイ

- 設定だけで済むもの: 学校用の Supabase（`VITE_SUPABASE_URL` など）、Vercel のプロジェクト（`API_ORIGIN`、Production Branch を `release`）、VM の `stack.env`、GitHub のルールセット（`release` も必須のチェックの対象にする）。
- VM は、今の手順のままでは作りません。今の手順（`deploy/risepath-vm/README.md`、`doc/guides/risepath_vm_deployment.md`、`provision-gce.sh` の案内）は、既定のブランチ（`main`）を clone し、名前を `risepath-vm` にして、その前に Tailscale の管理画面から旧 `risepath-vm` を消すよう案内しています。学校の VM は、別の `VM_NAME` と Tailscale の名前で作り、`git clone -b release` で取り出して、GCP の削除の保護を付けます。公開版の `risepath-vm` は消しません。
- 既定のままにするもの: AI アプリをつなぐしくみ（`byoa`）、課金（`BILLING_ENABLED`）、モデルの鍵、設定の画面からの本人の削除（`ACCOUNT_DELETION_ENABLED`。学校の退会のページができるまで）。学校の Supabase の OAuth サーバーも有効にしません（有効にすると、AI アプリが本人としてログインし、4.2 の守りを通るおそれがあります。[ai-access-plan.ja.md](ai-access-plan.ja.md) 5.3）。Nexloom の設定（`VITE_NEXLOOM_*`）は入れません。
- 規約のページのフラグ（`VITE_FEATURE_LEGAL_PAGES`）は、学校の規約を書面で知らせるあいだ（D4）は既定のままにします。アプリに学校の文を出すときは、学校のビルドでだけ `true` にし、ビルドの確かめ（`vite.config.ts:58` の `legal-release-guard`）が学校の文を見るようにします。
- 学校の Supabase で、パスワードの条件と、続けて失敗したときの制限をどう設定できるかを確かめます（ログインはブラウザから Supabase に直接届くので、API では失敗を数えられません）。無料枠で使うなら、一時停止を防ぐ毎日の keepalive を置きます。
- コードが要るもの: 教材の API とサーバーでの採点、訓練の画面、教材を api だけに届ける設定、学校用の CI、P-School などを隠すフラグ、毎日のバックアップ、学校用の規約の切り替え。
- 公開の前の確かめ（Phase 9）は、一般向けの版のためのものです。Vercel のビルドの確かめ（`scripts/deploy/vercel-env-rules.mjs` の VB2）は `VITE_FEATURE_TRAINING=true` のビルドを止め、VM の事前チェック（`scripts/deploy/preflight-rules.mjs` の C6）は `TRAINING_ENABLED` のある `stack.env` を止めます。このコードが `release` に入る前に、学校の版でだけ通す切り替えを作ります（設定だけでは済みません）。

### 4.8 CI

- 新しいジョブは `ci.yml` に足します（`e2e.yml` のジョブは、`server/tests/e2eWorkflow.test.js` が 3 つに固定しています）。既存のジョブ名は変えません（ブランチのルールが名前で必須にしているため。[ai-access-plan.ja.md](ai-access-plan.ja.md) 11.2）。
- 新しいジョブでは学校用のフラグでビルドし、訓練の見本の問題に埋めた答えの目印が出ないことを確かめます。今の公開のビルド（`Build and key-leak scan`）でも、同じ目印と訓練の画面のコードが出ないことを確かめます（法務の文の検査と同じ形）。どちらのビルドの画面のファイルも、ログインなしで取れるためです（3 章）。
- `*.csv`・`*.dump`・`*.sql.*` のファイルが変更に入っていたら、CI を落とします（`scripts/ci/check-assets.mjs` と同じ形。migration の `.sql` は止めません）。`.gitignore` と `.vercelignore` にも `*.csv` を足します。

### 4.9 受講時間の数え方

数え方は `shared/training/studyTime.js`（版 `study-time/v1`）の純粋な関数で、DB にも画面にも依らずにテストします（`server/tests/trainingStudyTime.test.js`）。値は書かず、名前と意味だけをここに書きます（D9）。

- 受講時間の画面は、一定の間隔で合図を送ります。合図が持つのは、単元・画面の続き（chain。画面が見えている一続きの間）の ID と通し番号・止まったか（画面を隠した、離れた）・画面が選ばれていたか（focus）・操作があったか（input）だけです。時刻と長さは送りません。サーバーが、ロックのあとに DB の時計で受け取った時刻を付けます。
- 数えるのは、同じ画面の続きの、となりあう 2 つの合図のあいだです。間が `gapMs` を超えたら途切れとして数えず、1 回に数えるのは `creditCapMs` までです。
- 数えるのは、操作のあった合図から `idleMs` のあいだだけです。画面は、受講者が画面を開いた・見えるようにした・単元を変えたときに始める続きの最初の合図を、操作ありとして送ります（画面が自分で始め直すときは送りません）。止まった（stop）あとの合図は数えません。`requireFocus` なら、選ばれていない画面も数えません。
- 同じ瞬間は 1 回だけ数えます（D11）。違う単元の画面が重なったら、`overlap` の決まりで 1 つを選ぶか、どちらも数えません。
- 単元ごとに、単元表の設定時間（`setMinutes`）を、期の中の累計の上限にします。超えた分も、超えた分として残します。
- 日本時間の 0 時で日を切ります。ある日は、その日の終わり + `gapMs` を過ぎると変わらなくなります（確定）。
- 集め方の値（合図の間隔 `beatMs`、同じ画面の合図の最短の間 `minSpacingMs`、合図を記録する開いた画面の数 `maxPlaces`。新しい画面から数えます。数えるときは、同じ瞬間に 1 つの画面だけを数えます）と、数え方の値（`gapMs`・`creditCapMs`・`idleMs`・`requireFocus`・`overlap`）は、非公開の規則のファイルにあり、学校の DB に版として入れます（`shared/training/timeRules.js` が形を確かめます。既定値はなく、値がなければ数えません）。単元と設定時間は、非公開の単元表（`risepath.training-course/v1`、`shared/training/courseManifest.js`）から入れます。
- 合図を受け取るかどうかは `admitSignal` で決めます。設定がない・期間の外（開いている続きは、最後の日の終わり + `gapMs` まで受け取ります）・単元表にない単元・別の期や単元で使った続きの ID は断ります。同じ合図の繰り返し・止まったあとの合図・サーバーの知らない続きの途中からの合図・時計が進んでいないとき・短すぎる間隔・`maxPlaces` を超えた古い画面の合図は記録しません。
- 受講時間は 4 つのプルリクエストに分けます: 1. 数え方（このファイルと規則・単元表の形。DB は変えません）、2. 記録とサーバー（次の番号の migration、職員のスクリプト、退会の印）、3. 画面、4. 数え直しと確かめ（D12）。

## 6. 受け入れているリスク

- **公開のコード**（D9）: 公開のまま進めると、訓練の機能のコードは公開になり、取り消せません（Apache-2.0）。答え・設定値・受講者の情報は、コードの外に置きます。
- **公開版の DB にも表ができる**: migration はデプロイを区別しません（4.3）。
- **`release` は毎晩の確かめの外**: GitHub の定期実行は既定のブランチ（`main`）でしか動きません。`release` への push では CI が動かず、必須のチェックのルールセット（[ai-access-plan.ja.md](ai-access-plan.ja.md) 11.2 の 1）も、対象は `main` だけです。`release` を作るときに、同じ必須のチェックを `release` にもかけるルールセットを作り、プルリクエストで CI を通してから入れます。
- **`release` へのセキュリティの修正**: 公開のリポジトリでは、`main` に入れた修正を見れば穴が分かります。セキュリティの修正は、`main` に入れた日に `release` にも入れ、学校の VM にも同じ日に出します。`SECURITY.md` は「メンテナンスするのは最新の `main` だけで、リリースのブランチはない」としているので、`release` を作るときに、対象の版（英語の Supported versions も）に `release` を足します。
- **VM の起動のしくみ**: 教材の置き場所を重ねファイルで足すときは、起動のユニットも直します。直さないと、再起動でマウントが外れるおそれがあります（推測）。
- **P-School**: 学校用の Supabase には P-School の表がないので、学校のビルドでは隠します（推測）。

## 7. まだ分からないこと

次のことは、実施機関と専門家に確かめてから決めます。確かめた内容は、非公開の計画用リポジトリに残します。

- 受講時間の数え方（合図の間隔、操作がないときの扱い）
- 1 日を出席とする条件と、出席簿の作り方
- 障害で記録できなかった時間の扱い
- ログアウトの知らせが届かないとき（タブを閉じた、セッションが切れた）の終わりの時刻。最後の合図の時刻を使ってよいか
- 同じアカウントで 2 か所目にログインしたときの扱い
- 教室で同じアドレスから受講するときの人数と、全体の回数制限
- 記録の保存期間と、受講者から削除を求められたときの扱い
- 動画を使うか、再生の速さの扱い
- LMS のソースを公開していてよいか、仕様書にどこまで書くか

## 8. やらないこと

- 訓練の記録を `lesson_progress` から作ること

- 実施機関とのやりとり、不正を見つけるための設定値、受講者の情報、訓練の不具合を、このリポジトリ・issue・プルリクエストに書くこと
